Result: **BLOCKED (external prerequisite)** — the launcher package `@kaidera-ai/cortex` that `/cortex preflight` and `/cortex install` shell out to is **not published on npm** (E404), and no `cortex` launcher is on PATH. On a host without a running appliance the shipped 0.1.12 `/cortex install` therefore cannot deploy anything; it reports the launcher failure (exit 1) rather than a silent success. Prerequisite owner: the Cortex package owner (KOS row "CORTEX GITHUB PACKAGE", pending). W3 REWORK candidate: `/cortex preflight|install` must say "launcher not available yet — install Cortex from github.com/Kaidera-AI/cortex" when neither `cortex` nor the npm package resolves, instead of surfacing an npm 404 tail.

## Addendum — a `cortex` launcher IS on this Mac's PATH (`~/.local/bin/cortex`, installed after Inc 06); the shipped command prefers it over npx:

```
$ cortex --version; cortex preflight
cortex dispatcher 0.2.0
project: /Users/amadmalik/DevVault/OpenKai
cortex: VERB_NOT_FOUND — no cortex-preflight in /Users/amadmalik/DevVault/OpenKai/.agents/scripts
  cwd: /Users/amadmalik/DevVault/OpenKai
  hint: see 'cortex help' for verbs; try 'cortex which preflight'
exit=
```

So on THIS host the `cortex` on PATH is the **KOS dispatcher 0.2.0** (routes verbs to a project's `.agents/scripts/cortex-<verb>`), not the installer: `cortex preflight` → `VERB_NOT_FOUND`. The shipped `/cortex preflight|install` prefers whatever `cortex` is on PATH, so on a KOS-tooled Mac it fails with VERB_NOT_FOUND and on a fresh host it fails with the npm 404. Result stands **BLOCKED** on the installer package publication, plus a W3 REWORK: detect the dispatcher vs the installer (`cortex --version` prefix) and never route `preflight|install` to the dispatcher.
