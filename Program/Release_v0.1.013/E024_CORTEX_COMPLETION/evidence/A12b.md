## Addendum 4 — REVISED VERDICT (2026-09-04): the picker path FAILS on this appliance

Observed on cortex-test (:8601, project openkai-acceptance), token only ever loaded in a subshell:

1. **Model swap is not servable.** `PATCH /admin/cortex/config` to `local/BAAI/bge-base-en-v1.5` is accepted and `/health` reports it, but the forced backfill then errors with `local embedding provider key is not configured for cortex-api`, while `POST /memory` keeps returning 200 and `/degradation` stays `[]`. The only servable local model is the one the embed-worker container was started with (`sentence-transformers/all-mpnet-base-v2`). The OpenAPI has no provider-config create route (`embedding_provider_config_id: None`, only GET/PATCH `/admin/cortex/config`), so nothing the picker offers today (Ollama rows, cloud rows, or any other local model) can actually embed.
2. **Enrichment is backfill-only.** Rows are never embedded at write time on this stack; they sit in `/beat/embeddings/backlog` until `POST /beat/embeddings/backfill` (admin) or the maintenance beat runs. Search still answers lexically meanwhile, which is why the marker was "found in 5 s" earlier — that was not a vector hit.
3. **`POST /memory` upserts by `source` alone.** Same source, different content → same id, `action: updated`, the previous content is gone (probe: only "row 2" survived). Different category or different section with the same source → still the same id. Different source → new row. The fork writes with constant sources (`openkai/cortex-ingest`, `openkai/cortex_record`, `openkai/memory-save`, `tools/learn.ts`'s source, transcript `openkai`), so at most ONE row per write path survives — every new learning overwrites the last. Production (:8501, project openkai, read-only): `/cortex-graph/memory` has 0 nodes and 0 sources and a knowledge-flavoured search returns 0 results, so nothing has been lost there yet.

Verdict: A12b **FAIL** for the picker → appliance path (1); the settings/provider-file round trip itself works. New row A20 (memory retention) **FAIL** (3). Cortex findings row 1e35fbe1 filed to kai@kaidera-os (see PLAN amendment 2026-09-04).
