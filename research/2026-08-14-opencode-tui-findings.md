# OpenCode TUI — research findings for OpenKai

Date: 2026-08-14. Sources: opencode.ai docs (fetched live) + the `anomalyco/opencode` monorepo cloned at commit `4643e65` (2026-08-14, `dev` branch). Note: the repo has **moved from `sst/opencode` to `anomalyco/opencode`** — all doc "edit page" links and `package.json` repository fields now point there. Licence: **MIT** (repo `LICENSE`, copyright "2025 opencode").

## 1. What it is

OpenCode is a terminal-first AI coding agent: a headless server plus a TUI client, shipped as a single binary/npm package (`opencode`). It is one of the largest agent-harness projects in existence: **~197k GitHub stars, ~25k forks, ~5.2k open issues, commits pushed the same day as this research** (GitHub API, 2026-08-14). Current version in-tree: `@opencode-ai/tui` 1.18.18. Docs claim support for **75+ LLM providers** via models.dev. The TUI is built on **OpenTUI** — a native Zig terminal-UI core with TypeScript bindings and a SolidJS reconciler (`anomalyco/opentui`, ~13k stars, MIT, also actively committed). OpenTUI's README: "a native terminal UI core written in Zig with TypeScript bindings. The native core exposes a C ABI and can be used from any language."

## 2. Architecture map

Bun/TypeScript monorepo (turbo, bun workspaces, Effect-TS used heavily in newer core code). Relevant packages under `packages/`:

- `tui/` — `@opencode-ai/tui`, the TUI itself. SolidJS on `@opentui/solid` + `@opentui/core` 0.4.5 + `@opentui/keymap` 0.4.5 (bun catalog pins in root `package.json`). Entry `src/index.tsx`; routes (`src/routes/home`, `src/routes/session`), contexts (`src/context/*.tsx` — sdk, sync, event, theme, permission, keymap), dialogs (`src/component/dialog-*.tsx`), theming (`src/theme/` + 33 built-in JSON themes in `src/theme/assets/`).
- `opencode/` — the main CLI/server package (`bin/opencode`). Subdirs: `server/` (HTTP API, effect-httpapi), `bus/` (global event bus, Node `EventEmitter`), `session/` (agent loop, prompt processor, compaction, revert), `snapshot/` (git-based undo), `storage/` (JSON-file storage with migrations), `provider/` (model/provider registry), `auth/`, `permission/`, `question/`, `cli/cmd/` (tui, attach, run, serve, web, acp, mcp, db, …), `cli/tui/` (TUI worker thread host).
- `core/` — `@opencode-ai/core`, shared primitives: `models-dev.ts` (model catalogue fetch/cache), `event/` (EventV2 bus), `database/`, `oauth/`, `npm.ts` (dynamic provider npm loading), global paths.
- `sdk/js/` — generated OpenAPI client (`src/gen/`) plus a hand-written `v2` client (`src/v2/gen/types.gen.ts` holds the full SSE event union).
- `session-ui/`, `ui/`, `web/`, `desktop/` — SolidJS shared component packages and the web/desktop surfaces that reuse the same server.
- `plugin/`, `protocol/`, `schema/`, `llm/`, `effect-drizzle-sqlite/`, `effect-sqlite-node/` — plugin API, wire schemas, and newer SQLite-backed infrastructure.

**Process model (the important part):**
- Running `opencode` starts a **server in the main thread and the TUI in a Bun `Worker` thread** (`packages/opencode/src/cli/cmd/tui.ts`). With no `--port/--hostname`, all HTTP is tunnelled over worker RPC: the worker gets a synthetic base URL `http://opencode.internal`, a `createWorkerFetch(client)` fetch proxy, and an in-memory `createEventSource(client)` event feed — zero loopback sockets in the default path. Passing `--port`/`--hostname` ("external" mode) switches to real HTTP + SSE with basic-auth headers (`ServerAuth.headers()`).
- `opencode serve` runs the headless HTTP server standalone (default `127.0.0.1:4096`, optional `--mdns` discovery, `--cors`, basic auth via `OPENCODE_SERVER_PASSWORD`/`OPENCODE_SERVER_USERNAME`).
- `opencode attach <url>` attaches a TUI to an already-running server — including over the network with `--password`. There is also a `--mini` minimal interface with session replay on resume/resize.
- The same server also serves `opencode web`, ACP (Zed), IDE plugins, and a `/tui/*` endpoint family that lets external tools drive a running TUI (append/submit prompt, open dialogs, show toast, long-poll control channel `/tui/control/next`).

**Event protocol (server → client):** SSE at `GET /global/event` (global) and per-project `/event`. Handler: `packages/opencode/src/server/routes/instance/httpapi/handlers/event.ts`. Wire format is `data: {"id","type","properties"}` with ascending event IDs; the stream opens with a synthetic `server.connected`, filters events to the caller's `directory`+`workspaceID`, emits `server.heartbeat` every 10 s, and terminates on `server.instance.disposed`. The full v2 event union is generated at `packages/sdk/js/src/v2/gen/types.gen.ts` — types include `session.created|updated|deleted|status|idle|diff|error|compacted`, `message.updated|removed`, `message.part.updated|delta|removed`, `permission.updated|replied`, `todo.updated`, `file.edited`, `file.watcher.updated`, `lsp.*`, `vcs.branch.updated`, `installation.update-available`, plus reverse-channel `tui.prompt.append|toast.show|command.execute`. Token streaming is `message.part.delta` with `{sessionID, messageID, partID, field, delta}` — the client appends `delta` onto the named string field of an existing part (`packages/tui/src/context/sync.tsx` ~L398), so streaming costs one string concat per part, no re-render of the whole message.

**Client state model:** the TUI keeps a full client-side mirror of server state in a Solid store (`packages/tui/src/context/sync.tsx`): `session[]`, `message[sessionID][]`, `part[messageID][]`, `permission[sessionID][]`, `question[sessionID][]`, `todo`, `session_diff`, `lsp`, `mcp`, `formatter`, `provider`, `agent`, `command`. Initial load is REST; afterwards the SSE stream patches the store with `reconcile()`/sorted-binary-insert (`search()` + splice), so messages/parts stay ordered without refetch. SSE events are batched into 16 ms windows before emission so a burst of deltas produces one render (`packages/tui/src/context/sdk.tsx` `flush()`); reconnect uses capped exponential backoff (1 s → 30 s).

## 3. Capability inventory (only requested areas)

- **Multi-provider abstraction:** Vercel **AI SDK** (`ai` package, `LanguageModelV3` interface) + **models.dev** catalogue. `packages/core/src/models-dev.ts` fetches `https://models.opencode.ai` (a models.dev mirror; overridable with `OPENCODE_MODELS_URL`), caches `models.json` in the global cache dir with a **5-minute TTL** and a **cross-process file lock** (`Flock`) so concurrent CLIs don't race the cache. Model metadata is rich and schema-validated: cost incl. cache read/write and >200k tiers, reasoning options (`effort`/`toggle`/`budget_tokens`), interleaved-thinking field variants, status (`alpha`/`beta`/`deprecated`). Custom providers are **npm packages loaded at runtime** (`Npm` in core; e.g. `"npm": "@ai-sdk/openai-compatible"` with a `baseURL` — the documented pattern for any OpenAI-compatible local server). Auth: `/connect` TUI flow stores keys in `~/.local/share/opencode/auth.json`; OAuth flows (browser authorize/callback endpoints in the server API) for providers like GitHub Copilot; per-provider `blacklist`/`whitelist` for the model picker; provider transforms (`provider/transform.ts`) normalise model quirks.
- **TUI tech:** OpenTUI 0.4.5 (Zig core, C ABI, Solid reconciler, shared `@opentui/keymap` engine). Native renderables include `<diff>` (used directly as JSX in `permission.tsx` and `diff-viewer.tsx`), `<scrollbox>` with macOS-style scroll acceleration, textareas with full readline/emacs editing keybinds. Diff layout: `diff_style: "auto"` → split view when terminal width > 120 cols, unified/"stacked" otherwise.
- **Session/context management:** sessions form a **tree** — subagent runs are child sessions (`parentID`), not nested tool output. Server APIs: fork at message, revert/unrevert (git snapshot), summarize (compaction), share/unshare, diff-per-session, children listing. Undo/redo is implemented by a **shadow git repository** (`packages/opencode/src/snapshot/index.ts`): separate `--git-dir` under the global data dir per project+worktree with `objects/info/alternates` pointing at the user's repo, hash-keyed patches, 7-day prune, 2 MiB file limit. Storage is JSON files with a migration runner (`storage/storage.ts`); newer SQLite packages exist in-tree for v2 data. Hidden system agents (`compaction`, `title`, `summary`) run as ordinary primary agents with prompts, not special-cased code paths.
- **Subagent/orchestration:** primary agents (Build/Plan) + subagents (`general`, `explore`, `scout`), invoked via the `task` tool or `@mention`. Agents are markdown files with frontmatter (global `~/.config/opencode/agents/`, project `.opencode/agents/`) or JSON config; per-agent model, temperature, max steps, and **permission overrides**. Subagent child sessions are first-class navigable sessions (footer hint "view subagents", `<leader>↓` to enter child, ←/→ to cycle siblings, ↑ to parent). Experimental background subagents exist (`capabilities.experimentalBackgroundSubagents`, `background !== true` metadata filter in the TUI).
- **Memory/vector/embeddings:** none — no vector store, no embeddings, no retrieval. Long-term state is files (AGENTS.md rules, JSON storage) only. [Confirmed by absence: no embedding/vector code in `packages/core`, `packages/opencode`.]
- **Packaging/distribution as an embeddable module:** the TUI is a private workspace package but exposes ~30 fine-grained `exports` (contexts, keymap, config, plugin runtime, UI primitives) that the CLI package imports — i.e. it is consumed as a library in-process, not as a binary. The whole app ships as one npm package with a `bin/opencode` shim plus per-platform binary installs (curl installer in `install/`). The server is the embeddable unit: OpenAPI 3.1 spec at `/doc`, generated JS SDK, and other-language SDKs in `sdks/`.

## 4. Delta findings (NOT in the KOS baseline)

1. **Repo governance change:** opencode now lives at `anomalyco/opencode` (not `sst/opencode`); OpenTUI at `anomalyco/opentui`. Both MIT. The docs footer shows "© Anomaly". Any pinned URLs in KOS docs referencing `sst/opencode` should be updated (GitHub redirects currently work).
2. **Worker-thread TUI with RPC-tunnelled HTTP:** the default opencode session has **no socket at all** — server in main thread, TUI in a Bun worker, fetch + event subscription proxied over worker RPC with a fake origin `http://opencode.internal` (`packages/opencode/src/cli/cmd/tui.ts` L220-245). The *same client code* runs against real HTTP+SSE when `--port` is passed. This is the cleanest known answer to "in-process vs client/server": abstract `fetch` + an `EventSource`-shaped subscription, and swap transports.
3. **SSE event protocol specifics worth copying wholesale:** synthetic `server.connected` first frame; **10 s `server.heartbeat` frames**; per-connection filtering by `directory` + `workspaceID`; terminal `server.instance.disposed` event so clients can distinguish "server gone" from network failure; ascending event IDs (`Identifier.create("evt", "ascending")`) enabling binary-search insertion in client stores. Heartbeats and disposed-events are the two things most hand-rolled SSE streams (including KOS's) tend to skip.
4. **Field-level delta events:** `message.part.delta` carries `{partID, field, delta}` — one event type streams text, reasoning, and tool-input JSON by naming the target field, keeping the wire uniform and the client trivial (string append). KOS's `delta` event could gain a `field` dimension instead of growing per-kind delta types.
5. **16 ms client-side event batching:** SSE events queue and flush at ~60 fps so a token burst = one Solid render (`sdk.tsx` `flush()`/`last`). Also capped-backoff reconnect (1 s→30 s) that tolerates server restarts transparently.
6. **Subagent permission bubbling:** the parent session route aggregates `permission[]` and `question[]` **from all child sessions** and blocks its own input while any child prompt is pending (`routes/session/index.tsx` `permissions`/`questions`/`disabled` memos). One prompt queue for the whole session tree — no "invisible subagent waiting for approval" deadlock. KOS's dispatch model has no equivalent; this is a direct fix for a real multi-lane failure mode.
7. **Shadow-git undo/redo:** snapshots use a separate `--git-dir` with `objects/info/alternates` into the user repo — file-history for undo without touching the user's git state, with 7-day prune and 2 MiB/file cap (`snapshot/index.ts`). Enables `/undo`, `/redo`, revert, fork-at-message, and per-session diff "for free".
8. **Permission engine semantics:** three actions (`allow`/`ask`/`deny`), **last-matching-rule wins** wildcard patterns (`*`, `?`), per-agent overrides, pattern-specific bash rules (`"git *": "ask"`), `external_directory` guard for paths outside the worktree, `doom_loop` guard (same tool call 3× with identical input → prompt), `.env` files denied-by-default via the read rule, and an `--auto` global auto-approve mode that still honours explicit `deny`. The "ask" UI offers **once / always (remember pattern for this session) / reject** — the "always" option writes back a session-scoped pattern rule, which is what makes ask-mode livable.
9. **models.dev as the single source of model truth:** one JSON catalogue (cost, cache pricing, >200k tiers, reasoning capabilities, status) fetched with 5-min TTL + cross-process flock; providers themselves are AI-SDK npm packages, includable at runtime by config (`"npm": "@ai-sdk/openai-compatible"`). Adding a provider = config entry, not code. 75+ providers documented.
10. **The TUI is remotely drivable:** `/tui/append-prompt`, `/tui/submit-prompt`, `/tui/open-sessions|themes|models`, `/tui/show-toast`, `/tui/execute-command`, and a long-poll control channel (`/tui/control/next` + `/tui/control/response`). IDE plugins use this to drive a running TUI. For OpenKai this means the KOS orchestrator could drive an operator's TUI directly (prefill a handoff prompt, toast on gate failure) over the same HTTP API the TUI itself uses.
11. **mDNS discovery + basic auth:** `opencode serve --mdns` advertises the server on the LAN; `OPENCODE_SERVER_PASSWORD` protects it. `opencode attach http://host:4096` then gives a full TUI to a remote/headless server — the cheap multi-machine story KOS currently lacks.
12. **Attention system:** per-event sound packs + terminal-mediated desktop notifications (only when the terminal is blurred), separately configurable for `question`, `permission`, `error`, `done`, `subagent_done` (`tui.json` `attention.*`). Long-running agent sessions need exactly this "come back when needed" channel; nobody else's TUI has it this configurable.
13. **Agents-as-markdown with permission frontmatter:** an agent is a `.md` file with `description`/`mode`/`model`/`temperature`/`permission` frontmatter in well-known dirs; hidden *system* agents (title generation, compaction, summary) are the same mechanism — the system prompt pipeline is user-inspectable and user-overridable by construction.
14. **No memory layer at all:** despite its scale, opencode has zero vector/embedding/retrieval infrastructure — deliberate scope. KOS's Cortex (pgvector lessons/decisions/trajectories) is genuinely *ahead* here; OpenKai should treat memory as its differentiator, not copy opencode.
15. **`--mini` replay interface:** a minimal interactive mode that replays session history on resume and after terminal resize (`--replay-limit`) — a graceful-degradation story for dumb terminals worth noting for OpenKai's TUI.
16. **Experimental background subagents:** server advertises `capabilities.experimentalBackgroundSubagents`; the TUI filters running foreground `task` parts and offers a "background" shortcut. Capability flags in the handshake (`server.connected`/config) let client and server evolve independently.

### TUI UX patterns worth copying

Each item verified in docs and/or source:

1. **Leader-key keybind namespace** — `ctrl+x` leader with 2 s `leader_timeout` for all app commands, leaving plain keys for typing; every bind is user-overridable or `"none"`-disableable in `tui.json`, merged over defaults. ([docs/keybinds](https://opencode.ai/docs/keybinds/))
2. **Command palette (`ctrl+p`)** over the same command registry as slash commands and keybinds — one command surface, three invocation styles; palette-only settings (e.g. username display, auto-approve toggle) persist automatically. ([docs/tui](https://opencode.ai/docs/tui/), `packages/tui/src/component/command-palette.tsx`)
3. **Which-key popup** — discoverable overlay of pending keybind groups (`which_key_toggle` etc. in the default keymap). ([docs/keybinds](https://opencode.ai/docs/keybinds/))
4. **`@` fuzzy file-reference autocomplete** in the prompt, including aliased external "references" roots (`@alias/` autocompletes inside another tree); file content is inlined into the conversation automatically. ([docs/tui#file-references](https://opencode.ai/docs/tui/))
5. **`!` prefix = run shell command, output enters the conversation as a tool result** — zero-friction context injection without a tool call. ([docs/tui#bash-commands](https://opencode.ai/docs/tui/))
6. **Prompt stash** — `prompt_stash`/`prompt_stash_pop`/`prompt_stash_list` keybinds park a half-written prompt while you run something else (`packages/tui/src/component/prompt/stash.tsx`, keybinds doc).
7. **Frecency-ranked prompt history** — history ranking by frequency+recency, not just MRU (`packages/tui/src/component/prompt/frecency.tsx`, `history.tsx`).
8. **Subagent sessions navigable as a tree** — footer hint "view subagents" under any message containing `task` parts; `<leader>↓` enter child, ←/→ cycle siblings, ↑ parent; permissions/questions from children surface in the parent ([docs/agents#usage](https://opencode.ai/docs/agents/), `routes/session/index.tsx` L1510-1531).
9. **Permission prompt with inline syntax-highlighted diff** — the edit-approval dialog renders the pending diff (split above 120 cols, stacked otherwise) in a scrollable, themed view, with a fullscreen toggle (`ctrl+f`); outcomes once/always/reject ([docs/permissions#what-ask-does](https://opencode.ai/docs/permissions/), `routes/session/permission.tsx` `EditBody`).
10. **`diff_style: auto` responsive diffs + diff wrap toggle** — split↔stacked by terminal width, word-wrap toggleable, persisted via KV ([docs/tui#configure](https://opencode.ai/docs/tui/), `permission.tsx` `view` memo).
11. **Undo/redo conversation+files as one operation** — `/undo` removes the last user message, subsequent responses, *and* the file changes (git snapshot), so the mental model is "rewind the world", not "delete text" ([docs/tui#undo](https://opencode.ai/docs/tui/), `snapshot/index.ts`).
12. **Session timeline + fork from any message** — `session_timeline` (`<leader>g`) dialog, fork creates a branched session at a chosen message (`routes/session/dialog-timeline.tsx`, `dialog-fork-from-timeline.tsx`; server `POST /session/:id/fork`).
13. **Session management dialogs** — list/switch (`<leader>l`), rename (`ctrl+r`), delete (`ctrl+d`), move-to-project, plus `/export` to markdown into `$EDITOR` and `/new`, `/compact`, `/share` (docs/tui command list).
14. **Toggleable thinking blocks, tool details, timestamps, generic tool output** — `/thinking`, `/details`, `session_toggle_timestamps`, `session_toggle_generic_tool_output`, all persisted per-user ([docs/tui](https://opencode.ai/docs/tui/), `routes/session/index.tsx` KV signals).
15. **Context-aware footer/status line** — connected MCP server count (error tint on failure), LSP count, current agent with per-agent colour, muted `auto` indicator when auto-approve is on; blinking disconnected state (`routes/session/footer.tsx`, `local.agent.color`).
16. **Model UX** — `/models` picker, favourites (`ctrl+f`), cycle-recent (`f2`/`shift+f2`), per-model effort/variant cycling (`ctrl+t`), provider connect (`ctrl+a`) without leaving the TUI ([docs/keybinds](https://opencode.ai/docs/keybinds/)).
17. **Attention sounds + desktop notifications for `permission`/`question`/`done`/`subagent_done`/`error`** — notifications only when the terminal is blurred; sound packs with per-event overrides ([docs/tui#attention](https://opencode.ai/docs/tui/)).
18. **Scroll acceleration + configurable scroll speed** — macOS-style gesture acceleration option, `scroll_speed` floor 0.001 ([docs/tui#configure](https://opencode.ai/docs/tui/)).
19. **Full readline/emacs input editing** — word movement/deletion, kill ring style `ctrl+k/ctrl+u/ctrl+w`, select-all, input undo/redo (`ctrl+-`/`ctrl+.`), multi-line via `shift+return` variants, bracketed-paste with paste-summary toggle ([docs/keybinds](https://opencode.ai/docs/keybinds/) input_* defaults).
20. **Theming done right** — 33 built-in JSON themes; `system` theme derives a greyscale from the terminal background and uses ANSI 0-15 so it always matches; user/project theme dirs with override precedence; dark/light variants per token; `none` = terminal default; full token coverage incl. diff and markdown/syntax scopes ([docs/themes](https://opencode.ai/docs/themes/), `packages/tui/src/theme/assets/`).
21. **Terminal-cursor & mouse configurability** — cursor style/blink in input fields, mouse capture toggleable so native selection still works when off ([docs/tui#configure](https://opencode.ai/docs/tui/)).
22. **Toast + dialog primitives everywhere** — server can push `tui.toast.show` to any attached client; consistent `DialogSelect`/`DialogPrompt`/`DialogConfirm` components (`packages/tui/src/ui/dialog-*.tsx`, SDK event list).

## 5. Reuse verdict for OpenKai

| Item | Verdict | Notes / licence constraint |
| --- | --- | --- |
| **Client/server split with transport-abstracted `fetch` + event subscription (worker-RPC in-process, HTTP+SSE external)** | **Adapt pattern** | Direct fit: KOS already has console+SSE; OpenKai's TUI should code against a `fetch`+`EventSource` interface and get in-process tunnelling "for free" when embedded, real HTTP when attached to a headless KOS server. MIT — free to copy ideas; code is TS/Effect, not directly liftable into Python. |
| **SSE wire protocol details (server.connected, 10 s heartbeat, ascending IDs, directory/workspace filtering, disposed sentinel, `{id,type,properties}` envelope)** | **Adopt as protocol design** | Maps cleanly onto KOS's normalised event contract (session\|delta\|thinking\|tool\|result\|error\|done); add heartbeat + connected + ID sequencing to KOS's stream. No code needed. |
| **Field-addressed part deltas (`message.part.delta {partID, field, delta}`)** | **Adapt pattern** | Unify KOS `delta`/`thinking` streaming behind one delta event with a `field` discriminator. |
| **Client-side mirror store + 16 ms batching + reconcile-on-event** | **Adapt pattern** | Whichever TUI stack OpenKai picks needs this or it will re-render per token. |
| **OpenTUI (Zig core + Solid) as TUI dependency** | **Optional adopt** | MIT, C ABI, production-proven at 197k-star scale, and an OpenKai TS TUI could literally reuse opencode's component vocabulary. But it drags OpenKai into the Bun/TS ecosystem; a Python-native TUI (Textual) keeps KOS homogeneous. Decide per the OpenKai language call — do not mix both. |
| **models.dev catalogue + AI-SDK-style provider packages loaded by config (`npm:` field, baseURL override, blacklist/whitelist)** | **Adopt as dependency (catalogue) + adapt pattern (loader)** | models.dev is a public dataset (https://models.dev, MIT-licensed project) — consume the JSON; the "provider = config entry pointing at an OpenAI-compatible endpoint" loader pattern kills per-provider code. Note opencode caches `models.opencode.ai` — either mirror or tolerate the 5-min-TTL fetch. |
| **Permission engine (allow/ask/deny, last-match-wins globs, per-agent override, external_directory, doom_loop, once/always/reject with session-scoped remember)** | **Adapt pattern wholesale** | Fills KOS's "no quality gate" gap at the tool-execution layer; the `doom_loop` and `.env`-deny defaults are cheap, high-value copies. |
| **Shadow-git snapshot undo (`--git-dir` + object alternates, 7-day prune)** | **Adapt pattern** | Language-agnostic trick (shells out to git); gives OpenKai undo/revert/fork with zero risk to the user's repo. |
| **Child-session tree + permission/question bubbling to parent view** | **Adapt pattern** | Requires subagent runs to be sessions (KOS lanes already are) — then the UX is straightforward and solves the stranded-approval deadlock. |
| **TUI remote-control endpoints (`/tui/*` + control long-poll)** | **Adapt pattern** | Lets KOS gates/handoffs drive the operator's TUI (prefill prompt, toast) — a fusion-UX differentiator. |
| **Attention/notification system (sounds, blurred-terminal desktop notifications, per-event config)** | **Adapt pattern** | Small surface, big perceived quality; pair with KOS's 8-gate dispatch events. |
| **Session sharing via hosted service (opncd.ai/s/<id>)** | **Ignore for now** | Requires a hosted sync service + privacy posture KOS doesn't need; Cortex work_products already cover internal handoff. Revisit if OpenKai gets a cloud tier. |
| **Markdown-defined agents with permission frontmatter + hidden system agents (compaction/title/summary)** | **Adapt pattern** | KOS already has skill/agent files; adopt the "system tasks are just hidden agents" uniformity. |
| **`--mini` degraded terminal mode with replay** | **Adapt pattern (low priority)** | Nice resilience story for SSH/dumb terminals. |
