# RuVector — Research Findings (2026-08-14)

Target: https://github.com/ruvnet/RuVector (main branch root; `examples/ruvLLM` excluded — covered separately). Local shallow clone inspected at commit `74d2a60` (2026-08-13 18:30 UTC — one day before this report; extremely active).

## 1. What it is

RuVector is a **Rust-native persistent memory substrate for AI agents**: an embedded vector database plus graph store, self-learning layers (SONA MicroLoRA + EWC++), temporal/coherence retrieval, and a pgrx PostgreSQL extension marketed as a drop-in pgvector replacement. It is a Cargo workspace monorepo of **~176 crates** under `crates/`, plus ~60 npm packages under `npm/`. Maturity signals: 4,419 stars, 583 forks, 244 open issues, MIT licence, daily commits, published on crates.io (`ruvector-core`) and npm (`ruvector`, `@ruvector/core`, `@ruvector/wasm`). Despite the breadth, the README's own "Known boundaries" section concedes many components are research-grade or incomplete (see §4) — breadth >> depth.

## 2. Architecture map

- **Layout**: single Cargo workspace (`Cargo.toml`, workspace version `2.3.0`, Rust ≥1.77). `crates/` holds ~176 crates; heavy/exotic builds (`crates/rvf/*`, `ruvector-postgres` (pgrx), several wasm cdylibs, Tauri app) are **excluded from the default workspace build**. `npm/` holds napi-rs native packages with per-platform binaries (`*-darwin-arm64`, `*-linux-x64-gnu`, `*-win32-x64-msvc`, …) plus wasm packages.
- **Process model**: embedded/in-process first (Rust crate or Node napi addon; no server required). Optional `ruvector-server` HTTP surface, MCP server (`ruvector mcp start` with `RUVECTOR_MCP_ALLOW`/`DENY` tool policy), CLI (`npx ruvector hooks remember|recall|reembed|stats`), and hosted `mcp-brain` shared-memory plane. Replication/raft are local primitives with simulated transport, not a network plane.
- **Persistence**: single-file store (`storagePath`, reopen recovers vectors+metadata+config); **cold start enumerates all stored vectors and rebuilds the HNSW index** (stated boundary #4). Snapshots (`ruvector-snapshot`: compressed, checksummed, full-only — incremental/cloud/restore incomplete), copy-on-write branches and hash-linked witness logs via the RVF "cognitive container" format (`crates/rvf`, separate toolchain).

## 3. Capability inventory (contract-scoped)

- **Multi-provider abstraction**: `EmbeddingProvider` trait in `ruvector-core/src/embeddings.rs`; built-in local ONNX embedder (`OnnxEmbedder`, `all-MiniLM-L6-v2`, 384-dim, query/passage roles, provenance tracked per ADR-210), Candle and remote-API providers in the AgenticDB typed layer. This is an embedding-provider abstraction, not an LLM-provider abstraction — no chat-model routing lives here (that is ruvLLM's lane).
- **TUI tech**: none. CLI + MCP only; irrelevant to OpenKai's TUI.
- **Session/context management**: `AgenticDB` (`crates/ruvector-core/src/agenticdb.rs`) persists Reflexion episodes, skills, causal edges, learning sessions, policy state (Q-values), session turns (`SessionStateIndex`) and a hash-linked `WitnessLog`. `ruvllm::context::AgenticMemory` offers a unified working/episodic/semantic/procedural API **but is in-memory only and its consolidation method is a stub** (boundary #2). Compaction policies (LRU/LFU/coherence) exist in `ruvector-agent-memory` but are **not wired into the default persistence path** (boundary #6).
- **Subagent/orchestration**: none in the root repo (orchestration lives in sibling projects claude-flow/ruflo).
- **Memory/vector/embeddings**: core `VectorDB` (insert/search/delete/filter, cosine/euclidean/dot), HNSW + flat + `turbo4` indexes (`ruvector-core/src/index/`), LSM-tree ANN for high-write streams (`ruvector-lsm-ann`, L0 mutable + background L1/L2 compaction), DiskANN/SPANN crates for SSD scale, hybrid sparse+dense fusion (`ruvector-hybrid`, ADR-256), predicate-aware ANN (`ruvector-acorn`), multi-vector MaxSim late interaction (`ruvector-maxsim`), Matryoshka coarse-to-fine (`ruvector-matryoshka`), PQ (`ruvector-pq-search`), 1-bit RaBitQ (`ruvector-rabitq`), GNN reranker (`ruvector-gnn-rerank`, ADR-194), temporal decay + coherence gating (`ruvector-temporal-coherence`, ADR-211), graph/hypergraph store with Cypher (`ruvector-graph`, v2.3.1), SONA self-learning (`crates/sona` v0.2.1: MicroLoRA adapters, EWC++ anti-forgetting, trajectory/reward recording, reasoning bank).
- **Packaging/distribution as embeddable module**: first-class. crates.io `ruvector-core` (2.3.0); npm `ruvector` + `@ruvector/core` (0.1.17) via napi with prebuilt binaries for glibc Linux x64/arm64, macOS x64/arm64, Windows x64; `@ruvector/wasm` for browser; `ruvector-postgres` (2.0.6) as a pgrx extension (PG 14–17, Docker image `ruvnet/ruvector-postgres`). MCP server with read-only profile and explicit tool allow/deny env policy.

## 4. Delta findings (not in the KOS baseline)

1. **A credible in-Postgres pgvector replacement already exists**: `ruvector-postgres` is a pgrx extension (v2.0.6, PG 14–17) claiming **143 SQL functions**: vector ops, GNN layers, 46 attention mechanisms, **local embedding generation inside Postgres via 6 fastembed models (no external API)**, **full Cypher engine + SPARQL 1.1 in SQL**, hybrid vector+BM25 fusion (RRF/linear), hyperbolic (Poincaré/Lorentz) distance, sublinear graph solvers (PageRank/Laplacian O(log n)–O(√n)), self-healing index integrity checks (Stoer-Wagner mincut), neural DAG query-plan learning (59 SQL functions), row-level multi-tenancy. If even half is production-real, this directly addresses KOS Cortex's "no retrieval step / unmined trajectories" gaps without leaving the Postgres estate. Claims are vendor README — treat as [UNVERIFIED] until built and benchmarked; it requires the pgrx toolchain and is excluded from default builds.
2. **Benchmark honesty event**: `docs/benchmarks/BENCHMARK_COMPARISON.md` (2025-11-25) publicly **retracts prior "100–4,400× faster than Qdrant" claims as fabricated** (hardcoded multipliers in test code). Consequences: (a) there are **no trustworthy published head-to-head numbers vs pgvector/Qdrant/LanceDB** — any such RuVector numbers circulating are the retracted ones; (b) the retraction plus the brutally candid "Known boundaries" list is a positive governance signal. Verified internal numbers only (Apple M4 Pro / Linux, Rust 1.91–1.92): SIMD distance 384-dim ≈ 47–60 ns/op (≈17–19 M ops/s); HNSW k=10 @1k×128d = 61 µs (≈16.4k QPS); 10k×384d search ≈ 623 QPS p50 1.57 ms, dropping to ~113–143 QPS at 50k×384d — respectable embedded numbers, **not** server-class, and no recall targets published beside them.
3. **Temporal decay + coherence gating as pure scoring multipliers** (ADR-211, `ruvector-temporal-coherence` v0.1.0): `TemporalSearch` = `cos × exp(-λ·age)`; `CoherenceSearch` = `cos × ((1-w)·decay + w·gate)` where `gate(m) = degree(m)/max_degree` over an adjacency graph of memories above a cosine threshold. Decay is a multiply on the scan (zero extra I/O); gate is an O(1) array lookup per candidate; graph build is one-time O(n²) (approximate k-NN graph planned). Uniform `VectorSearch` trait across variants. **This is trivially portable to pgvector as SQL scoring over an `accessed_at`/`created_at` column plus a precomputed degree array** — we do not need the crate to steal the mechanism.
4. **Witness log + RVF cognitive containers**: hash-linked tamper-evident append log (`WitnessLog` in AgenticDB), full snapshots with checksums, **copy-on-write memory branches** (isolated experiments over one store, git-like). No equivalent in pgvector; directly relevant to Cortex's run_span trajectory auditability and to "branch the agent's memory before a risky experiment".
5. **Self-learning is trajectory-triggered, not read-triggered**: SONA MicroLoRA adapter updates, EWC++ consolidation, outcome-aware routing and graph shortcut edges fire only from **recorded outcomes/rewards** — "reading or searching memory does not, by itself, mutate learned weights" (README). This is a disciplined answer to the self-poisoning risk that any "self-learning memory" pitch usually glosses over; matches KOS's handoff-gate philosophy. SONA itself is research-grade [INFERENCE: fine for OpenKai v2, not v1].
6. **Capability-gated ANN** (`ruvector-capgated`, ADR-268): per-vector 64-bit read masks enforced *inside* the ANN traversal (not post-filter), with documented side-channel/recall caveats. A concrete mechanism for multi-tenant memory isolation that pgvector's post-filter approach handles poorly (selective filters collapse recall — RuVector's own boundary #3 concedes the same failure mode for its core filtering and points to ACORN as the fix).
7. **ACORN predicate-aware ANN** (`ruvector-acorn`): selective metadata filtering without post-filter recall collapse — the known pgvector pain point (filtered HNSW over-fetching) addressed structurally.
8. **Honest incompleteness map** (README "Known boundaries", verbatim substance): unified 4-type memory has no save/load and consolidation returns nothing; core `DbOptions.quantization` field is persisted but **not applied**; persisted-HNSW cold start rebuilds index by full enumeration; temporal coherence is O(n²) proof-of-concept; compaction unwired; snapshots full-only; **replication/Raft are local primitives with simulated transport — not a production network plane**; GNN rerank/MRAgent/Darwin optimisation are research surfaces, not automatic in `VectorDB::search`. Any adoption must treat the repo as a parts catalogue, not a product.
9. **Distribution details worth copying for OpenKai**: napi per-platform optional-dependency binary packages + wasm fallback + `npx <pkg> info` backend self-report; MCP server with `*_MCP_PROFILE=readonly` and env-based tool allow/deny lists; CLI advice to **pin and install locally** rather than `@latest` in hooks — all directly applicable to OpenKai's installable-module design.

## 5. Reuse verdict for OpenKai / KOS Cortex

| Item | Verdict | Licence constraint |
|---|---|---|
| `ruvector-postgres` (pgvector replacement) | **Evaluate as dependency candidate** for Cortex: build it (pgrx 0.12.9 toolchain), run our lessons/decisions/work_products workload against pgvector baseline; adopt only if embeddings-in-DB + Cypher + hybrid fusion measurably beat pgvector+app-side code. Do not commit pre-benchmark — vendor comparison table is unverified marketing. | MIT; pgrx build burden; excluded from default workspace build |
| Temporal decay + coherence gate scoring (ADR-211) | **Adapt pattern** — implement `score = cos × exp(-λ·age) × gate` in SQL/Python over existing pgvector tables; no new dependency. Directly answers Cortex's "no retrieval step" gap and supersedes hourly unmined pruning with graded decay. | MIT; mechanism is 3 formulae |
| AgenticDB typed memory (Reflexion episodes, skills, causal edges, session turns, witness log) | **Adapt pattern** — schema inspiration for mining Cortex run_span trajectories into typed lessons/decisions; witness-log hash chaining for audit. | MIT |
| Learning-from-outcomes-only discipline (SONA trigger model) | **Adopt principle** in OpenKai fusion/memory design: retrieval never mutates learned state; only gated outcomes do. | n/a (design principle) |
| `ruvector-core` / npm `ruvector` as embedded store | **Ignore for KOS** (Cortex is Postgres-centralised; a second embedded store fragments memory). Reconsider only if OpenKai needs an offline laptop-mode memory with zero Postgres. | MIT |
| SONA MicroLoRA/EWC++, GNN rerank, RVF containers, Raft/replication, mcp-brain | **Ignore (v1)** — research surfaces with self-declared incomplete paths; revisit at OpenKai v2 for learned relevance. | MIT |
| npm/napi distribution + MCP policy surface | **Adapt pattern** for OpenKai packaging: per-platform optional deps, wasm fallback, `info` self-check, readonly MCP profile, allow/deny env lists. | MIT |

Overall: **augment, not replace.** Keep Postgres as the Cortex system of record; treat RuVector as (a) a pattern library for decay/coherence/typed-memory/witness-log, and (b) one candidate (`ruvector-postgres`) to benchmark as a pgvector successor. Nothing here justifies a hard dependency yet.
