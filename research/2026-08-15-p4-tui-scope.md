## 1. What P4a is

The OpenKai TUI exists: `openkai` (bare) launches a pi-tui alt-screen application that runs the P2 single-lane loop through the P2 `SessionTransport` — streaming text, tool-call cards, resumable sessions, droid-grade design discipline from the first frame. `openkai chat` (print mode) stays; the TUI is the same transport with a different renderer — that is the proof the OK-3 abstraction works.

**Non-goals (P4b+, listed in §7):** permission engine, subagent tree + bubbling, shadow-git undo, attention notifications, leader-key palette, mermaid→ASCII, onboarding flow. Do not build them in this slice.

## 2. CPO amendments (ren REWORK verdict) folded into this scope

- **A1 — Run modes are first-class.** *standalone-local*: no `CORTEX_PROJECT` or API unreachable → local-only persistence (JSONL tree), no crash, status chrome shows `local`. *KOS-managed*: project resolved + API reachable → checkpoints on, chrome shows project key. The TUI must never hard-require Cortex (ADR D3: usable outside KOS by anyone).
- **A2 — Protocol authority + versioning.** The P2 `SessionEvent` contract is frozen as **`openkai.session.v1`** and documented here as the versioned contract: connected-first frame, monotonic `seq` per session, field-addressed deltas (`{kind:"delta", field:"text"|"thinking", partId, delta}`), terminal `session_end`. v1 has **no approval channel** — remote approval injection is banned by absence, not by policy.
- **A3 — Retention boundary.** Raw session JSONL is operator-local state (`.openkai/sessions/`, deletable, gitignored). `/sessions/ingest` is the derived store; ingest must strip `thinking` content by default (redaction-at-ingest knob) and is always project-scoped by the API. Reconciliation with E015's 30-day raw retention + derived distillation is P5 learning-loop work — recorded, not built here.
- **A4 — Sequencing repaired.** This slice is the minimal TUI the ADR's P1 wording anticipated; P1/P2's print surfaces were observers.

## 3. Design system (droid bar, OK-5) — day-one rules

1. **Tokens module is the only colour source.** `packages/cli/src/tui/theme.ts`: `surface-1/2/3`, `text`/`text.muted`, `highlight`/`highlightDanger` (danger lives in the highlight of risky rows, not just labels), muted-left-border blocks for tool output. Ad-hoc colour literals anywhere else = review defect.
2. **One interaction grammar.** Every overlay carries the identical footer: `↑/↓ Navigate · Enter Select · ESC Cancel`.
3. **Clean by default.** Thinking content hidden behind `Ctrl+O` (density toggle); spinner reflects true turn state; fixed-width chips so state cycles never reflow the composer.
4. **Persistent visible state.** One status chrome line, always present: mode (`chat`), model id, session id (short), token usage, persist mode (`local`/project key). Model/mode single-key cyclable is P4b — P4a shows them.
5. **Double-Esc clears the draft.** Third-Esc rewind menu is P4b.

## 4. Build surface (pi-tui 0.84.2 — verified installed exports)

```
packages/cli/src/tui/
  app.ts            — TuiAltScreen root; layout VStack: transcript(ScrollView) + composer(Editor) + status(Text)
  transcript.ts     — message blocks (Markdown), tool-call cards (muted-left-border), streaming append per delta.partId
  composer.ts       — Editor wiring: Enter submits, history (frecency is P4b), double-Esc clears draft
  status.ts         — the chrome line (§3.4); updates on usage/turn_end events
  theme.ts          — design tokens (§3.1); THE ONLY colour source
  commands.ts       — SlashCommand provider: /help /model /sessions /resume <id> /new /quit
  keymap.ts         — KeybindingsManager: Ctrl+O density, Esc grammar, Ctrl+C quit-with-confirm
packages/cli/src/index.ts
  — bare `openkai` / `openkai tui` → TUI; `chat`/`sessions`/`events` unchanged
```

Loop wiring: `InProcessTransport` (P2) drives the loop; `events()` feeds the transcript renderer. `Ctrl+C`/`/quit` → `transport.abort()` + `close()` + session store flush. Session resume: `openkai tui --session <id>` or `/resume` — loads the v3 tree, replays entries into the transcript, continues the branch (new entries parent at the tree leaf).

**Renderer rules:** text deltas append to the current message's Markdown block (re-render block, not screen); thinking deltas buffer into a collapsed-by-default section behind the density toggle; `tool_call` opens a card, `tool_result` settles it (args summary + result preview, truncated); `usage` updates the chrome; `turn_end` settles the block.

## 5. Testing (replaces the ADR's `@factory/tui-test` adoption)

`@factory/tui-test` is **not published** (npm 404, verified 2026-08-15) — OK-5's adopt item is corrected here: use pi-tui's own headless renderability. Two test layers, both deterministic and offline:
1. **Golden-frame tests** (vitest or node:test — execution picks, repo has no test runner yet, add exactly one dev dep): boot the TUI against pi-ai's `faux` provider (`@earendil-works/pi-ai` exports `providers/faux`) scripted to stream a canned reply + one tool call; capture rendered frames headlessly; assert key cells/regions (chrome line present with model id; tool card border; footer grammar on overlays). Snapshots committed.
2. **Event-mapping tests**: `SessionEvent` sequences → transcript state (thinking hidden by default; revealed after toggle; usage lands on chrome at `turn_end`).

Live smoke (manual evidence for the return): real OpenRouter run if the worker env has the key — one prompt, screenshot/capture of the frame; otherwise the faux-provider golden run is the acceptance evidence and the gap is stated.

## 6. Verification (acceptance)

1. `npm run build && npm run typecheck` green from clean.
2. `node --test` (or vitest) green: golden-frame + event-mapping tests.
3. `openkai tui` boots headlessly against the faux provider: scripted turn renders streamed text + one tool-call card + chrome updates; captured frames attached as evidence.
4. Mode matrix: with `CORTEX_PROJECT` unset → chrome shows `local`, zero Cortex calls, session still persists locally; with it set → ingest checkpoint fires (visible in `/sessions/ingested-ids`).
5. `openkai chat` and `openkai events --print` regressions: unchanged behaviour.

## 9. Risks

- **pi-tui headless capture** may need xterm.js headless glue — if the capture path fights back, fall back to asserting on the component tree's rendered line buffer (pi-tui renders to lines internally) and state that substitution in the return.
- **Editor component keybind collisions** with the Esc grammar — verify double-Esc detection against pi-tui's `Key`/`matchesKey` before composing custom handlers.
- **Markdown re-render cost** per delta — throttle transcript block re-render to animation-frame cadence (opencode's 16ms batching, OK-3) if flicker appears.
