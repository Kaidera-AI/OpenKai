# Ruflo — research findings for OpenKai

## 1. What it is

Ruflo is **claude-flow v3 rebranded** (ADR-046, `v3/implementation/adrs/ADR-046-ruflo-rebrand.md`): ruvnet's "agent meta-harness" that wraps Claude Code and Codex with an MCP server (323 tools), a CLI (45 top-level commands), a hooks/routing layer, swarm coordination, and a self-learning memory stack. Its own positioning: "Agent = Model + Harness… Ruflo is the harness". Maturity signal: ~67.9k stars, 8.1k forks, MIT licence, TypeScript, very active (commits on 2026-08-14, day of research). Root `package.json` is still named `claude-flow@3.38.9` with bin `claude-flow`; the `ruflo` npm package is produced by `scripts/prepare-root-publish.mjs`, so both brands ship from one tree. Repo URL is `github.com/ruvnet/ruflo`; several badges/issue links still point at `ruvnet/claude-flow` (same project history).

## 2. Architecture map

- **Runtime**: Node ≥20, ESM TypeScript. Monorepo-ish layout: root package + `v3/` workspace (`v3/@claude-flow/cli`, `v3/@claude-flow/shared`, `v3/@claude-flow/guidance`, `v3/@claude-flow/codex`, `v3/@claude-flow/plugin-agent-federation`, `v3/@claude-flow/security`), plus `v3/plugins/*` (TS plugins, some with Rust→WASM sub-crates, e.g. `v3/plugins/gastown-bridge/wasm/*`).
- **Core domains** (`v3/src/`): `agent-lifecycle/`, `coordination/application/SwarmCoordinator.ts`, `memory/infrastructure/{AgentDBBackend,HybridBackend,SQLiteBackend}.ts`, `task-execution/application/WorkflowEngine.ts`, `infrastructure/mcp/`, `infrastructure/plugins/{Plugin,PluginManager,ExtensionPoint}.ts`.
- **MCP layer** (`v3/mcp/`): `server.ts`, `tool-registry.ts`, `session-manager.ts`, `connection-pool.ts`, transports `stdio.ts` / `http.ts` / `websocket.ts`; tool modules `agent-tools`, `swarm-tools`, `memory-tools`, `hooks-tools`, `sona-tools`, `worker-tools`, `federation-tools`, `task-tools`, `session-tools`, `system-tools`, `config-tools`, `v2-compat-tools`.
- **Process model**: single Node process for CLI/MCP (`bin/cli.js`, `bin/mcp-server.js`); long-running daemon + 12 auto-triggered background workers; agents themselves are either Claude Code/Codex sessions steered via hooks, or WASM-sandboxed "rvagent" agents; memory in `.swarm/memory.db` (sql.js SQLite + ONNX embeddings) and `.claude-flow/neural/*.json`.
- **Rust→WASM kernels** for policy engine, embeddings, and the verification proof system; optional native NAPI deps (`@ruvector/*`, `agentdb`, `better-sqlite3`) are `optionalDependencies` with WASM/JS fallbacks.

## 3. Capability inventory (OpenKai-relevant only)

- **Multi-provider abstraction**: thin. `v3/@claude-flow/cli/src/commands/providers.ts` catalogues Anthropic, OpenAI, Google, Ollama (cloud, OpenAI-compatible), plus Transformers.js embeddings and a mock provider. Real provider work is delegated to the `agentic-flow` dependency and, in the web UI, to OpenRouter (6 curated models + any OpenAI-compatible endpoint). The interesting part is not the provider SDK but the **router** (below).
- **TUI tech**: none. Surface is plain CLI (commander + chalk + inquirer), Claude Code **statusline daemons** (ADR-052), and two self-hostable web UIs: `ruflo/src/ruvocal/` (chat UI, multi-stage Dockerfile with optional embedded Mongo, `cloudbuild.yaml` for Cloud Run) and `v3/goal_ui/` (Vite + Supabase GOAP planner dashboard). No terminal UI library anywhere in the tree.
- **Session/context management**: MCP `session-manager.ts` + `session-tools.ts`; `ruflo init` writes `CLAUDE.md`, `.claude/`, `.claude-flow/` into the host project; memory bridge imports Claude Code's own memory files into AgentDB with `source:"claude-code"` attribution.
- **Subagent/orchestration**: 45 agent-definition markdown files under `plugins/*/agents/` and `.claude/agents/` (queen-coordinator, hierarchical/mesh/adaptive coordinators, raft-manager, byzantine-coordinator, gossip-coordinator, crdt-synchronizer, hive-mind collective-intelligence, scout/worker/swarm-memory-manager). Coordination via `SwarmCoordinator.ts`, swarm-comm hub (messaging, pattern broadcast, consensus voting, task handoff), GOAP A* goal planner.
- **Memory/vector/embeddings**: AgentDB (HNSW, optional native NAPI), ReasoningBank pattern store (`.claude-flow/neural/patterns.json`), SONA self-optimising adaptation (WASM), Q-learning router (`.swarm/q-learning-model.json`), MoE 8-expert gating, EWC++ consolidation, MicroLoRA, RaBitQ 1-bit + Int8 quantisation, ONNX `all-MiniLM-L6-v2` embeddings (384-dim) with observable mock fallback.
- **Packaging/distribution as an embeddable module**: npm package `ruflo` (also `claude-flow`), `npx ruflo init [wizard]`, `curl|bash` installer, Claude Code plugin marketplace (35 `plugins/ruflo-*` packages), Docker images for the web UIs, `ruflo eject` to turn a ruflo project into a standalone renamed agent toolkit. It is a **host-integrated** harness (writes into your repo), not an embeddable library.

## 4. Delta findings (NOT in the KOS baseline)

1. **Meta-harness via hook injection, not a runtime.** Ruflo's primary track does not run its own agent loop; it installs hooks, an MCP server, a generated `CLAUDE.md`, and routing rules into Claude Code, then lets Claude Code's own loop call its 323 tools. "You don't need to learn 314 MCP tools… the hooks system automatically routes tasks" (README). This is a fundamentally different integration posture from KOS's lane-wrapping orchestrator: influence the host harness's loop rather than spawn it.
2. **Hooks as a learning-wired routing layer.** `HookRegistry`/`HookExecutor` with five priority bands (Critical 1000 → Background 1), ten lifecycle events (PreToolUse/PostToolUse/PreEdit/PostEdit/PreCommand/PostCommand/PreTask/PostTask/SessionStart/SessionEnd), and MCP tools `hooks/route` + `hooks/explain` (transparent routing decisions), `hooks/pretrain` (bootstrap intelligence from the repo itself, incl. git history), `hooks/metrics`, `hooks/transfer <sourceProject>` (port learned patterns between projects) — `v3/implementation/hooks/README.md`.
3. **Swarm-communication primitives KOS lacks.** Agent-to-agent messaging, **pattern broadcast** (a high-quality learned pattern is pushed to all agents; peers import via `swarm-import-pattern`), consensus voting with generated guidance text, and a **task-handoff payload schema** carrying `filesModified`, `patternsUsed`, `decisions`, `blockers`, `nextSteps` — a concrete schema for inter-agent context transfer beyond KOS's handoff files (`v3/implementation/hooks/README.md` §Swarm Communication).
4. **Measured learning loop, honestly audited.** Their own empirical audit (`docs/reviews/intelligence-system-audit-2026-05-29.md`) confirms a real RETRIEVE→JUDGE→DISTILL loop: success/failure verdicts move persisted pattern confidence (0.906→1.0→0.952 across processes); Q-learning route feedback flips the greedy agent pick cross-process; MoE expert probability moved 0.081→0.994 after 200 rewards; SONA WASM `instantAdapt` measured 0.0042 ms; Int8 = 3.92× memory at cosine 0.99999; RaBitQ = 32× memory (real WASM 1-bit index).
5. **Marketing-number debunk (cautionary engineering fact).** Same audit: "HNSW 150×–12,500×" measured **peak 1.48× at N=20k**, slower than brute force below N≈5k; "Flash Attention 2.49–7.47×" was literally `2.49 + Math.random()*4.98` at `attention-coordinator.ts:972`; "75× embeddings" had no benchmark. Remediation shipped (v3.10.7–3.10.9): fabricated metric removed, embedding backend now labelled `onnx|mock`, per-complexity-bucket bandit priors (ADR-142). Lesson: any performance claim OpenKai adopts must ship with its reproducer script, as ruflo now does (`scripts/benchmark-intelligence.mjs`).
6. **Real routing bandit design.** 3-tier model routing = static keyword-complexity heuristic **plus a persisted Beta (Thompson) bandit** that shifts model choice after `model-outcome` feedback; priors keyed per complexity bucket (low/med/high) so failures on one task type don't suppress a model globally (ADR-142). Directly applicable to OpenKai fusion provider/panel selection — a mechanism the E016 fusion ADR does not cover.
7. **Framework-overhead benchmark methodology.** Stub-LLM "Mode A" harness benchmarks vs LangGraph/AutoGen/CrewAI: cold start 3.93 ms (darwin) / 2.66 ms (linux), single-turn dispatch 0.019–0.053 ms, RSS ~61 MB, linear agent scaling to N=100 with **421k tool dispatches/sec**; explicit "Mode B (real LLM) pending" honesty. WASM-agent creation 0.018 ms. Source: benchmark gist + `docs/benchmarks/sota-workload-spec.md`.
8. **Zero-trust agent federation.** Cross-machine agent collaboration: mTLS + ed25519 challenge-response identity (no shared secrets), a 14-type PII detection pipeline on every outbound message with per-trust-level BLOCK/REDACT/HASH/PASS policies, behavioural trust scoring `0.4×success + 0.2×uptime + 0.2×threat + 0.2×integrity` (instant downgrade, history-gated upgrade), a **budget circuit breaker** (`maxHops: 8` default, constant-string errors `HOP_LIMIT_EXCEEDED`/`BUDGET_EXCEEDED` to avoid oracle leaks, ADR-097), HIPAA/SOC2/GDPR audit-trail modes, optional WireGuard mesh (ADR-111). Far beyond anything in the baseline.
9. **Install-integrity witness (`ruflo verify`).** Every shipped fix is Ed25519-signed keyed off the git commit; `ruflo verify` recomputes SHA-256 of installed files and checks the manifest signature — supply-chain proof for an npm-installed harness, with per-tool witness signing in flight (`verification.md`, `docs/STATUS.md`).
10. **Hardening details worth copying.** MCP stdin 10 MB cap against un-newlined-input OOM; loader-hijack env vars (`LD_PRELOAD`, `NODE_OPTIONS`, `DYLD_*`) denied at the terminal-create boundary; 0600 file modes on session/terminal/memory stores; opt-in AES-256-GCM at rest with magic-byte `RFE1` format for backward-compatible migration (ADR-096); command-injection sweep across git/gh/npm call sites (`docs/STATUS.md`).
11. **Honest incapacity list.** The audit also flags implemented-but-inert pieces: WASM MicroLoRA `apply()` never flushes B (output delta 0.0 after 5000 adapts — unfixed, lives in upstream `@ruvector/ruvllm-wasm`); EWC++ "Fisher" is a heuristic proxy `|w|·λ`, not gradient curvature; MCP consolidation previously fed a synthetic `Math.sin()` gradient. Treat ruflo's "neural" claims as partially aspirational.
12. **`ruflo eject` / MetaHarness.** A harness that grades its own setup (1–100 readiness), scans tool configs for security risk, snapshots project state for regression diffing, and can **eject a project into a standalone, renamed agent toolkit** (`docs/metaharness-user-guide.md`). Novel distribution idea: the harness as scaffolding you can shed.

## 5. Reuse verdict for OpenKai

| Item | Verdict | Notes / licence |
|---|---|---|
| ruflo as a dependency | **Ignore** | MIT, but it is a host-integrated Claude Code/Codex plugin ecosystem, not an embeddable module; adopting it would swallow the whole `.claude/` + marketplace sprawl. |
| Hook-registry pattern (priority bands, lifecycle events, `route`/`explain`/`metrics` tools) | **Adapt pattern** | Maps onto KOS's existing dispatch gates; `explain` (transparent routing rationale) is a genuinely good DX idea for OpenKai's fusion router. MIT. |
| ReasoningBank RETRIEVE→JUDGE→DISTILL loop + pattern broadcast between agents | **Adapt pattern** | KOS Cortex already stores lessons/decisions/trajectories but never mines them; this is the missing feedback loop. Broadcast = shared learning across lanes. MIT. |
| Beta-bandit model routing with per-complexity priors (ADR-142) | **Adapt pattern** | Direct fit for OpenKai fusion provider selection; per-bucket priors are the non-obvious refinement. MIT. |
| Task-handoff payload schema (`filesModified`/`patternsUsed`/`decisions`/`blockers`/`nextSteps`) | **Adapt pattern** | Extends KOS's handoff-filed dispatch with a structured, learning-compatible schema. MIT. |
| Federation trust scoring + budget circuit breaker | **Ignore for now; revisit** | Out of OpenKai's current scope (single-machine harness+TUI); note the `maxHops` circuit breaker as prior art if multi-machine ever lands. MIT. |
| `verify`-style witness signing for distributed builds | **Adapt pattern (later)** | Relevant once OpenKai is an installable module with integrity expectations. MIT. |
| Stub-LLM Mode A / real-LLM Mode B benchmark methodology + mandated reproducer scripts | **Adopt practice** | Cheap, honest harness-overhead benchmarking; inoculates against ruflo's own fabrication failure mode. |
| WASM agent sandbox (rvagent), 323-tool MCP surface, plugin marketplace, hive-mind/queen nomenclature, web UIs | **Ignore** | Weight without OpenKai-relevant payoff; no TUI to borrow from (their surface is CLI + statusline + web). |
